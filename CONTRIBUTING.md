## Version Control

All changes made to python source files for a particular task should be performed on a new branch, then submitted as a pull-request so it may be reviewed alongside any other changes made by other group members, avoiding merge conflicts as much as possible.

Changes made to documentation, addition of new files, or any non-source files can be committed directly to the main branch.

## Keep changes small and focused

All group members should try their best to reduce the changes made per a given commit, such that those changes correspond to only a single task being completed. A single commit may still include more than a single edit and even changes across multiple files, but these changes should not impact the functionality of more than one behavior/function of the project.
